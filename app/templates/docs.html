What gets scanned

Only files that shape an AI coding agent's behaviour are read — everything else is ignored (and, for zip uploads and Git scans, never stored).

CLI (runs locally, nothing uploaded)

pip install "git+https://github.com/abhedit/AI-Coding-Agent-Security-Auditor"
agent-auditor scan .                       # human-readable
agent-auditor scan . -f sarif -o agent.sarif
agent-auditor scan . --fail-on critical    # CI gate
agent-auditor rules                        # list rules

Record results in {{ brand.brand_name }}

Create an API key under Settings, then:

export AGENT_AUDITOR_API_KEY=ags_...
export AGENT_AUDITOR_API_URL={{ brand.base_url }}
agent-auditor scan . --remote --project my-service

The CLI discovers agent config files locally and uploads only those files.

GitHub Action

name: agent-security
on: [pull_request, push]
permissions: { contents: read, security-events: write }
jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: abhedit/AI-Coding-Agent-Security-Auditor@main
        with:
          fail-on: high
          api-key: ${{ '{{' }} secrets.AGENT_AUDITOR_API_KEY {{ '}}' }}   # optional
          api-url: {{ brand.base_url }}
      - uses: github/codeql-action/upload-sarif@v3
        if: always()
        with: { sarif_file: agent-auditor.sarif }

Scoring

Scores start at 100. Each finding subtracts its severity weight (critical 25, high 12, medium 5, low 2), with repeats of the same rule discounted. Any critical finding caps the grade at D. Grades: A ≥ 90, B ≥ 75, C ≥ 60, D ≥ 40, F < 40.

Limitations

This is static analysis of configuration. It does not execute MCP servers (unlike some tools, it will never start a server from a scanned repo), so tool-poisoning checks need an exported tool manifest. Runtime prompt injection arriving through web pages, issues or tool output requires runtime guardrails in addition to this audit.
